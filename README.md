# 学祭POS システム

大学祭にて商品を販売するためのPOSシステム。1日約1000人来場を想定。
当日は **LAN共有モード**（1台のMac等でサーバーを起動し、同じWi-Fiの端末からアクセス）で運用する。

> 客用モバイルオーダー（`/order`）は要件から削除。全画面がスタッフ用（要ログイン）。

## 当日の起動（LAN共有モード）

**→ 詳しくは [LAN.md](LAN.md) を参照。**

1. **Docker Desktop を起動**しておく。
2. ターミナルで:
   ```bash
   cd ~/gakusaiPos && ./scripts/lan-up.sh
   ```
   MacのLAN IPを自動検出して設定・起動し、最後にアクセスURL（`http://<MacのIP>:3001`）を表示する。
3. 同じWi-Fiの各端末（iPad等）のブラウザでそのURLを開き、共通パスワードでログイン。
4. 停止は `docker compose down`。

> 注意: 全端末とMacは同じWi-Fiに。Macはスリープ無効で起動したまま。IPが変わったら `lan-up.sh` を再実行。
> 共通パスワードの初期値は `gakusai2026`。

## 機能概要

- **会計**：対面注文の会計。お釣り計算・番号発番。**テンキー＋キーボード入力**、**割引**、**管理者モード**（価格編集・売り切れ設定）。
- **調理担当**：注文番号×品目の表形式で表示。スペースキーで先頭注文を完了。
- **受け渡し（管理）**：受け渡し準備 → 呼び出し中 → 受け渡し完了 の3段操作。
- **受け渡し（客向け）**：お呼び出し中・準備中の番号をリアルタイム表示。全画面表示対応。
- **集計**：売上合計・注文数・割引合計、レジ別・商品別の売上をリアルタイム集計。

## 会計画面

- 商品タップでカートに追加、数量増減。**割引（¥）**を入力すると合計から差し引く。
- **お預かり**は**テンキー**または**物理キーボードの数字**で入力、**Enterで会計完了**。お釣りを自動計算。
- **管理者モード**：商品の**価格編集**・**売り切れ設定**（会計中は不可）。
- 会計完了で番号を発番し、お渡し番号を大きく表示。

## 注文番号ルール

3桁で管理。先頭がレジ（会計1=1／会計2=2）、末尾2桁 `XX` は **会計1・会計2で共有する単一の連番**（1〜50 を循環、レジをまたいで進む）。50 の次は 1 に戻る。

- 発番は DB の共有カウンタ行をロックして直列化し、同時発番でも番号が重複しない。
- **受け渡し完了していない使用中の XX はスキップ**する（アクティブな注文で番号が被らない）。1〜50 が全て使用中なら発番不可（409）。
- 例: `102` → `203` → `204` → `105` のように XX が共有で進み、先頭は発番したレジ。

| 端末 | 番号帯 |
|---|---|
| 会計1 | 1XX（XX=01〜50） |
| 会計2 | 2XX（XX=01〜50） |

## ステータスフロー

```
注文完了 → 会計完了 → 準備完了 → 呼び出し中 → 受け渡し完了
                                           （キャンセルは別途・論理削除）
```

- 会計画面は注文を直接 **会計完了** で作成する。
- 受け渡し（管理）: **準備完了**（受け渡し準備）→ 呼び出す → **呼び出し中** → 受け渡し → **受け渡し完了**（非表示）。
- ステータスは**前進のみ**許可（逆行・段飛ばし・終端からの復帰は拒否）。

| ステータス | 操作する画面 | 操作者 |
|---|---|---|
| 会計完了 | 会計 | 会計スタッフ |
| 準備完了 | 調理担当 | 調理スタッフ |
| 呼び出し中 | 受け渡し（管理） | 受け渡しスタッフ |
| 受け渡し完了 | 受け渡し（管理） | 受け渡しスタッフ |
| キャンセル | 会計（削除） | 会計スタッフ |

> 客向けモニターでは「準備中」=会計完了＋準備完了、「お呼び出し中」=呼び出し中 を表示。

## 各画面の仕様（抜粋）

**調理担当**
- 列=注文番号、行=品目の表形式。品目行は**常に全表示**（0も薄く表示）。
- 10件超えたら次の段（テーブル）に折り返し。
- スペースキーで先頭列（次の注文）を完了、番号ヘッダータップでも完了。

**受け渡し（客向け）モニター**
- お呼び出し中の番号を大きく緑表示、準備中を控えめに表示。右上の「⛶ 全画面」でフルスクリーン。

**集計**
- 売上合計（割引反映）・注文数・割引合計、レジ別（件数・売上）、商品別（販売数・売上）。
- 10秒ごとに自動更新＋手動更新。キャンセル注文は除外。

## サービス構成（docker compose）

| サービス | 内容 | ポート |
|---|---|---|
| frontend | Next.js 開発サーバー | 3001 |
| backend | Laravel API サーバー | 8001 |
| reverb | Laravel Reverb（WebSocket） | 8080 |
| queue | キューワーカー（ブロードキャスト配送） | — |
| db | MySQL 8.4 | 3307（ホスト）→ 3306（コンテナ） |
| redis | Redis 7 | 6379 |

> ホスト側の 3307 はローカルMySQLとの競合回避のため。コンテナ間は `db:3306` で接続。`DB_PORT_HOST` で変更可。

## セットアップ（開発・localhost）

```bash
git clone https://github.com/shuta1123/gakusaiPos.git
cd gakusaiPos
docker compose up -d --build
```

起動後:

- フロント: http://localhost:3001
- API: http://localhost:8001/api
- WebSocket: ws://localhost:8080

商品データは backend の起動時に自動でマイグレーション・シードされる。
スタッフ共通パスワードの初期値は `gakusai2026`（`docker-compose.yml` / `backend/.env` の `STAFF_PASSWORD`）。

> 当日のLAN共有運用は [LAN.md](LAN.md)、Ubuntuへの本番デプロイは [DEPLOY.md](DEPLOY.md) を参照。

## API エンドポイント

| メソッド | パス | 認証 | 説明 |
|---|---|---|---|
| POST | `/api/auth/login` | なし | 共通パスワードでログイン |
| POST | `/api/auth/logout` | 要 | ログアウト |
| GET | `/api/products` | 要 | 商品一覧 |
| PATCH | `/api/products/{id}` | 要 | 価格・売り切れ設定 |
| GET | `/api/orders` | 要 | 注文一覧（status/source 絞り込み可） |
| POST | `/api/orders` | 要 | 注文作成（discount 指定可） |
| GET | `/api/orders/{id}` | 要 | 注文詳細 |
| PATCH | `/api/orders/{id}/status` | 要 | ステータス更新（前進のみ許可） |
| DELETE | `/api/orders/{id}` | 要 | 注文キャンセル（論理削除・status=キャンセル） |
| GET | `/api/orders/next-number` | 要 | 次の注文番号（`?source=`） |
| GET | `/api/stats` | 要 | 売上集計 |

認証は共通パスワード由来の Bearer トークン方式（無期限）。ログイン以外の全 API がスタッフ認証必須。
